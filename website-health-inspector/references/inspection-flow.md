# 巡检总流程

一次完整巡检按以下顺序执行：

1. 加载标准资源清单。
2. 如启用页面发现，执行受控页面发现并合并页面。
3. 对网站页面执行内容审查。
4. 如配置管理员流程，执行浏览器自动化检查。
5. 如配置主机与微服务，执行健康检查。
6. 每个检查模块生成自己的子报告。
7. 合并子报告，形成最终 JSON。
8. 运行评分合理性复核，输出 `score-audit.json` 和 `score-audit.md`。
9. 评分审计通过后，渲染 HTML、Markdown 和摘要图片。
10. 生成 PDF、交付包和质量审计。

原则：

- 保留部分结果，不因单个模块失败而丢失整次巡检。
- 模块无法执行时，应输出 `unknown` 或明确的失败发现。
- 总报告必须优先展示管理结论，再展示技术证据。
- 评分审计是渲染前门禁；`score < 60`、重算分数不一致、状态与评分不一致或疑似重复扣分时，先阻断正式报告交付，只保留 JSON 和评分审计产物。
- 人工确认低分合理后，必须通过 `--score-review-approved --score-review-note "..."` 显式继续，批准说明会写入交付清单和技术附录。
- 健康状态与评分共用有效扣分模型；质量审计状态只表示交付质量，不能改变健康状态。
