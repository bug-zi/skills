# HTML 报告设计规范

报告视觉参考 Kami 风格：

- 暖纸色背景。
- 墨蓝色强调。
- 衬线标题层级。
- 克制使用红、琥珀、绿状态色。
- 正式简报感，而不是深色大屏或调试后台。

第一屏必须回答：

- 当前整体是否健康？
- 是否存在严重问题？
- 哪些系统受影响？
- 管理员下一步应优先处理什么？
- 健康评分对应的真实语义是什么，例如“前台可用，后台健康待复核”，不能只展示分数。

建议报告结构：

1. 封面摘要区。
2. 管理摘要图。
3. 检测员最终判定。
4. 审计员摘要与健康总览指标。
5. 巡检边界与下次复测清单。
6. 评分拆解、浏览器覆盖和关键截图证据链。
7. 严重问题与优先事项。
8. 系统健康矩阵。
9. 模块详情。
10. 技术证据附录。

设计禁忌：

- 不要堆满原始日志。
- 不要使用炫酷赛博风或深色大屏。
- 不要把所有信息做成同等权重的卡片。
- 不要让技术证据压过管理结论。
- 不要让“模块证据”停留在指标表；每个模块都应有检测员判定、证据结论、发现摘要和复核重点。
- 不要把登录未确认、受保护跳转、401 请求中断直接写成已确认故障；需要用诊断面板说明证据边界和闭环所需证据。
