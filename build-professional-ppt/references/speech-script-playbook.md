# 讲稿生成 Playbook

这一步在最终页面成图完成之后执行。目标不是把 PPT 上的字重复一遍，而是把每页内容转成真正能讲的文字稿。

## 适用场景

- 正式汇报
- 领导汇报
- 方案路演
- 高校申报答辩
- 项目介绍或成果汇报

## 输入材料

讲稿生成至少要基于这些内容：

- 最终页序
- 每页标题
- 每页一句话判断
- 每页最终成图
- 大纲文件
- 如果有原始讲稿，也只作为补充参考，不直接照抄

## 三类输出

默认同时输出三类文本：

### 1. `speech_script.md`

正式讲稿全文，适合完整预演或逐页朗读。

### 2. `speaker_notes.md`

简版提词稿，适合现场看重点。

### 3. `slide_speech_map.md`

逐页映射表，用来确认“第几页讲什么、怎么开口、怎么转场”。

## 逐页讲稿写法

每一页至少写四层：

1. 页面目的
2. 开口句
3. 展开解释
4. 转场句

推荐结构：

```markdown
## 第 3 页

### 页面标题
...

### 页面主判断
...

### 开口句
...

### 展开解释
...

### 转场句
...
```

如果后续要导出视频，`speech_script.md` 必须尽量保持这个结构，因为视频脚本会按 `## 第 x 页` 和 `### 开口句 / 展开解释 / 转场句` 读取逐页旁白。

## 不同页面的讲稿长度

- 封面页：短
- 章节页：短
- 观点页：中
- 架构页：中到长
- 案例页：中到长
- 数据页：中
- 尾页：短

原则：
- 转场页不要讲太满
- 重点页要讲清逻辑，而不是只念标题
- 尾页要收束，不要再开新话题

## 讲稿原则

- 先讲页面结论，再讲补充解释
- 语言要像汇报，不像论文或说明书
- 不要把页面文案逐条念一遍
- 不要脱离页面新增大段未出现的新结论
- 每页结尾最好有一句自然的过渡

## 讲稿常见问题

- 每页都像在读字
- 没有转场，像分裂的小段落
- 重点页讲太短，轻页面讲太长
- 页面是正式汇报风格，讲稿却过于口语化

## 视频导出友好要求

- 每页讲稿只对应一张最终页图。
- 讲稿页码必须和最终成图文件页码一致。
- 每页旁白长度要适合视频观看，不要一页讲得过长。
- 不要把字幕当成补充页面正文的地方。
- 如果后续需要男声、女声或字幕，参考 `references/minimax-tts-video-playbook.md`。

讲稿阶段默认不再生成额外视觉板，避免在母版确认和最终成图后增加无必要的中间图。
