# 审查与微调 Playbook

这份手册用于在逐页成图完成后，对整套 PPT 做系统审查，并直接完成可以当场处理的小幅统一微调。

目标不是只列问题，而是把能快速修平的地方先修平，再把真正需要返工的问题准确分流回前面的阶段。

## 审查范围

至少覆盖五个维度：

1. 逻辑
2. 内容
3. 样式
4. 布局
5. 一致性

## 审查顺序

建议固定按这个顺序检查：

1. 先看整套页序和章节推进
2. 再看每页标题和主判断
3. 再看每页信息单元是否完整
4. 再看样式系统是否统一
5. 再看布局、留白和对齐
6. 最后检查成图、大纲、讲稿、PDF 是否同版

不要一上来先调小细节，否则容易在逻辑还没稳定时浪费时间。

## 五个维度怎么查

### 1. 逻辑审查

重点检查：

- 页序是否顺
- 章节转场是否自然
- 重点页是否前置
- 架构页、案例页、结论页是否放在合适位置
- 是否存在两页讲同一件事
- 是否缺少承上启下的一页

常见问题：

- 开场太久，核心判断出现太晚
- 案例先于能力说明
- 架构页太早或太晚
- 结论页没有真正回应前文

遇到这些问题时：

- 如果只是个别页顺序轻微调整，先更新大纲，再同步成图和讲稿
- 如果叙事主线本身有问题，回退到 `PPT大纲*.md`

### 2. 内容审查

重点检查：

- 标题是否表达判断，而不只是目录名词
- 每页是否只有一个主判断
- 信息单元是否够支撑标题
- 是否有重复表述
- 是否有明显缺漏
- 案例页是否写清场景、动作、价值

常见问题：

- 标题太虚
- 正文很多，但没有主次
- 一页里混了两个判断
- 结构页没有解释层次

遇到这些问题时：

- 轻度问题可直接微调标题和正文层级
- 如果主判断变了，先改 `PPT大纲*.md`

### 3. 样式审查

重点检查：

- 字体是否统一
- 字号层级是否统一
- 字重、颜色、标题条、页签、页码是否统一
- 卡片、线条、圆角、阴影是否统一
- 图标语言、底纹和装饰是否统一
- 是否有几页突然变成另一套风格

常见问题：

- 标题字号忽大忽小
- 页面局部颜色偏出主色系统
- 某些页的卡片风格明显不同
- 局部图标过于花哨

这些问题通常优先直接微调，不必大返工。

### 4. 布局审查

重点检查：

- 标题区是否稳定
- 图片区是否压住正文
- 正文区是否足够清晰
- 边距、对齐和留白是否一致
- 页面是否有明确焦点
- 重内容页是否还能呼吸

常见问题：

- 图压字
- 字压图
- 左右边距飘
- 卡片没有对齐
- 页面头重脚轻

这些问题通常可以先做局部重排和微调；如果发现当前页型根本承载不住，再回退到逐页施工。

### 5. 一致性审查

重点检查：

- 成图页数和 `PPT大纲*.md` 页数是否一致
- 页面标题是否一致
- 页面主判断是否一致
- `slide_speech_map.md` 是否逐页对应
- `speech_script.md` 是否仍然匹配最终页序
- 最终 PDF 是否来自最新成图

如果一致性不对，不能只改一份文件，要同步整条链路。

## 可直接微调 vs 必须回退

### 可直接微调

这类问题优先直接处理：

- 标题区上下偏了几像素
- 页签、页码、分隔线不统一
- 标题字重、字号、颜色不统一
- 卡片底纹、圆角、阴影轻微漂移
- 图片裁切不齐
- 留白不匀
- 辅助图标风格偏差
- 个别页面视觉过满，需要补一点清理或平衡素材

### 必须回退

这类问题不要只修视觉表面：

- 叙事顺序错误
- 页面主判断错误
- 内容结构缺层
- 页型选错
- 视觉系统本身已经裂开
- 架构页或案例页的承载逻辑根本不成立

回退建议：

- 大纲问题：回到 `PPT大纲*.md`
- 设计系统问题：回到 `design.md` 或母版组
- 单页承载问题：回到逐页施工的 `5A-5H`

## 审查阶段也要用 `imagegen`

这一阶段不是纯文字校对，仍然要用 `imagegen` 产出图片资产。

常见用途：

- 生成审查对比板，把不一致页面并列观察
- 生成风格统一方向板
- 生成缺少的局部底纹、统一图标、轻补位素材
- 生成某类页面的统一标题承载修正版

审查阶段的 `imagegen` 原则：

- 只处理统一和补位，不重新发明一整套新风格
- 优先贴近现有母版和 `design.md`
- 需要机构身份时，继续保留真实建筑、真实场景和真实气质

## 审查报告输出

审查结论默认写入：

- `设计规范/review_report.md`

推荐结构：

```text
# 审查与微调报告

日期：
审查范围：
当前版本：

## 逻辑问题
- ...

## 内容问题
- ...

## 样式问题
- ...

## 布局问题
- ...

## 一致性问题
- ...

## 已直接微调的项目
- ...

## 需要回退重做的项目
- ...

## 本轮同步更新文件
- ...
```

## 审查后的动作顺序

固定按这个顺序推进：

1. 先写 `review_report.md`
2. 先处理可直接微调的问题
3. 再判断是否有必须回退的问题
4. 如果有回退，先改大纲或设计，再改页面
5. 再同步讲稿
6. 最后重导 PDF

## 常见错误

- 只写审查报告，不真正微调
- 把逻辑问题误当成样式问题来修
- 页面改了，但 `PPT大纲*.md` 没改
- 页面改了，但讲稿和 PDF 还是旧版
- 审查阶段重新发明一套新风格，导致前后不一致
