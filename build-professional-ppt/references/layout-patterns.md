# PPT 常见布局结构分析

这份文档用于在逐页施工前快速判断“这一页应该长成什么结构”。重点不是装饰风格，而是页面承载逻辑。

## 使用方式

每次开始一页前，先判断四件事：

1. 这一页的核心任务是什么
2. 这一页有多少个信息单元
3. 这一页是图主导还是字主导
4. 这一页的阅读路径应该怎么走

判断完之后，再从下面的常见布局结构里选一种主结构，不要同时混用三四种。

## 模版数量结论

这份文档分析了很多常见布局结构，但不代表一套 deck 真的要把它们全部做成模版。

内容页模版的明确建议是：

- 默认做 `5` 个内容页模版
- 常规范围是 `4-6` 个
- 不建议少于 `4` 个，否则整套内容页容易单调
- 不建议超过 `6` 个，否则基本不是模版系统，而是在逐页单做

推荐固定下来的 `5` 个内容页模版是：

1. 右承载型
2. 左承载型
3. 上下留白型
4. 中间留白型
5. 全白承载型

说明：
- 这 `5` 个是“内容页模版”，不是“全套页面类型”
- 封面、章节页、尾页、特殊架构页、特殊案例页可以单独做，不算进这 `5` 个内容页模版里
- 下面列出的 `16` 类常见布局结构，主要用于帮助把具体页面映射到这 `5` 个模版上

## 一、布局结构的四个判断维度

### 1. 信息密度

- 低密度：`1-2` 个核心判断，适合封面、章节、观点页、结论页
- 中密度：`3-6` 个信息单元，适合内容页、案例页、方法页
- 高密度：`6+` 个信息单元，适合对照页、表格页、重内容页、复杂案例页

### 2. 视觉主次

- 图主导：先看图，再读标题和文字
- 图文平衡：图和标题共同承载主题
- 文主导：图只做承托，重点是文字、表格或结构关系

### 3. 逻辑类型

- 观点型：讲一个判断
- 对照型：讲两组差异
- 枚举型：讲 `3-4` 个方面
- 流程型：讲步骤和顺序
- 架构型：讲层级、模块和关系
- 案例型：讲场景、做法和结果
- 收束型：讲结论、愿景和结束语

### 4. 阅读路径

- 左到右：适合左右分栏、对照、流程
- 上到下：适合步骤、列表、结论递进
- 中心展开：适合概念页、关系页、辐射型结构
- Z 形：适合图文交错和封面类页面

## 二、常见布局主结构

下面这些结构足够覆盖大多数正式 PPT 页面。先定主结构，再做细节变化。

### 1. 封面分栏型

适用：
- 封面
- 首页命题页

结构：
- 一侧放完整标题信息
- 一侧放建筑、场景或主题主视觉
- 信息区通常是稳定竖向块面

适合信息量：
- 低密度

`imagegen` 角色：
- 生成主视觉
- 生成封面氛围图
- 生成标题安全区氛围或左侧信息面板底图

风险：
- 主视觉太满，标题没有呼吸
- 标题太弱，像给图配说明

### 2. 章节转场型

适用：
- 大章节页
- 叙事转场页

结构：
- 一个大标题
- 一段短导语或一句引题
- 大面积气氛图或抽象转场图

适合信息量：
- 低密度

`imagegen` 角色：
- 生成章节气氛图
- 生成音乐性、文化性、仪式感的转场背景

风险：
- 内容写太多，失去转场感
- 背景像封面重复，节奏拉不开

### 3. 左文右图型

适用：
- 观点页
- 说明页
- 案例页
- 场景说明页

结构：
- 左侧标题与正文
- 右侧主视觉或案例图
- 视线先落标题，再向右侧图像移动

适合信息量：
- 中密度

`imagegen` 角色：
- 生成右侧主视觉
- 生成右侧场景图或建筑图
- 生成标题区轻纹理

风险：
- 右图太重，把左边文字压没
- 左边文字过多，版心失衡

### 4. 右文左图型

适用：
- 与左文右图页交替使用
- 需要形成节奏变化的连续内容页

结构：
- 左侧视觉
- 右侧标题和正文

适合信息量：
- 中密度

`imagegen` 角色：
- 生成左侧主视觉
- 为左侧图像预留干净边缘，避免干扰右侧文字

风险：
- 左右页来回切换但没有逻辑，显得刻意
- 左图细节太多，右侧标题抓不住

### 5. 中心观点型

适用：
- 核心判断页
- 定义页
- 一句话命题页

结构：
- 中心是一个大判断或大概念
- 四周只放轻辅助元素，不堆正文
- 强调“这一页只讲一件事”

适合信息量：
- 低密度

`imagegen` 角色：
- 生成中心承载氛围
- 生成四周辅助纹理或边角装饰

风险：
- 忍不住加太多解释，把中心结构打散
- 中心没做强，整页变空

### 6. 上下留白宽屏型

适用：
- 流程页
- 宽结构页
- 横向逻辑页
- 一屏展示多个阶段的页面

结构：
- 标题在上
- 主要内容横向展开
- 上下或两侧保留呼吸感

适合信息量：
- 中到高密度

`imagegen` 角色：
- 生成横向结构底板
- 生成宽幅流程气氛图
- 生成下边缘视觉承托

风险：
- 流程过长，字太小
- 横向塞太多节点，页面变拥堵

### 7. 双栏对照型

适用：
- before / after
- 问题 / 对策
- 传统 / 新方案
- 线上 / 线下

结构：
- 左右两栏权重相近
- 栏间要有清晰分隔
- 栏标题必须强，避免用户看不出比较关系

适合信息量：
- 中密度

`imagegen` 角色：
- 生成左右对照气氛底板
- 生成对照页图标或符号素材

风险：
- 两栏不对称，比较失真
- 一边全是字，一边全是图，逻辑断裂

### 8. 三卡片枚举型

适用：
- 三个原则
- 三个价值点
- 三类场景
- 三个能力模块

结构：
- 三个横向或纵向卡片
- 卡片要有统一节奏和同级关系
- 页面重点是并列，而不是递进

适合信息量：
- 中密度

`imagegen` 角色：
- 生成卡片底纹
- 生成三张统一风格的小图或图标板

风险：
- 三张卡片长短差太大
- 卡片内部层级混乱，像三个小页面硬拼

### 9. 四象限矩阵型

适用：
- 四类对象
- 四个能力象限
- 二维度分类

结构：
- 中心是逻辑坐标或关系焦点
- 四角或四块放分类内容
- 适合把复杂内容先压成四类

适合信息量：
- 中密度

`imagegen` 角色：
- 生成矩阵底板
- 生成中心关系气氛图
- 生成四组统一风格的象限标识

风险：
- 四象限内容本来不属于二维分类，却硬套矩阵
- 每个象限文字太多，看不出结构

### 10. 横向时间轴型

适用：
- 时间线
- 建设路径
- 演进过程
- 从现状到目标的推进页

结构：
- 从左到右依次阅读
- 节点之间需要明显顺序感
- 每个节点只承载一个关键信息

适合信息量：
- 中密度

`imagegen` 角色：
- 生成时间轴底板
- 生成节点装饰和演进气氛

风险：
- 每个节点都写一大段，时间轴变成说明书
- 节点之间没有层次，只是排成一排

### 11. 纵向步骤型

适用：
- 办事流程
- 服务闭环
- 操作步骤
- 任务执行逻辑

结构：
- 从上到下或从左上到右下连续阅读
- 强调步骤推进
- 常与箭头、编号或阶段卡组合

适合信息量：
- 中密度

`imagegen` 角色：
- 生成步骤承载条
- 生成编号底板或箭头骨架

风险：
- 步骤其实没有顺序关系，却硬写成流程
- 步骤太多，字太密

### 12. 分层架构型

适用：
- 平台架构
- 能力架构
- 系统分层
- 运行机制结构页

结构：
- 明显的上中下或里外层级
- 层与层之间关系清楚
- 模块之间最好保持同级对齐

适合信息量：
- 中到高密度

`imagegen` 角色：
- 先生成无字结构底板
- 生成层级容器、关系通道、图标占位

风险：
- 逻辑是清单，不是架构，却画成分层图
- 模块太多，层级关系反而更乱

### 13. 中心辐射型

适用：
- 一个核心对象辐射多个对象
- 数字员工能力外延
- 服务对象关系图

结构：
- 中心是一个核心概念
- 四周是外延对象、能力或场景
- 适合表达“一核多端”

适合信息量：
- 低到中密度

`imagegen` 角色：
- 生成中心容器和放射关系底板
- 生成外围图标容器

风险：
- 中心概念不够强，画面散
- 外围项目太多，辐射关系变蜘蛛网

### 14. 案例叙事型

适用：
- 典型案例
- 用户场景
- 场景化服务说明

结构：
- 一张场景主图
- 若干卡片说明“对象、动作、结果”
- 或者“场景、做法、价值”

适合信息量：
- 中密度

`imagegen` 角色：
- 生成案例情境图
- 生成人物、场所、业务动作的氛围画面
- 生成案例页角标和小图标

风险：
- 案例只有场景，没有结论
- 图像很热闹，但与汇报主题脱节

### 15. 数据看板型

适用：
- 指标页
- 数据结果页
- 多组数字对照页

结构：
- 数字是主角
- 图像只做弱支撑
- 卡片、图表、标签之间要严格对齐

适合信息量：
- 高密度

`imagegen` 角色：
- 只生成极轻底纹或装饰，不抢数据
- 可生成图标、标签底板、局部气氛图

风险：
- 用大主视觉抢占看板空间
- 看板像网页后台，不像汇报页

### 16. 结论收束型

适用：
- 总结页
- 展望页
- 尾页

结构：
- 一个主结论
- 一句愿景或行动口号
- 一个收束氛围图

适合信息量：
- 低密度

`imagegen` 角色：
- 生成夕景、收束感、希望感的尾页图
- 生成温和而不虚的结束氛围

风险：
- 结尾写成新内容页，失去收束感
- 情绪太满，像海报，不像汇报结尾

## 三、布局结构与母版类型的关系

如果这个 skill 已经先选定了母版类型，可以这样映射：

- `右承载型`
  适合：左文右图、案例叙事、观点页

- `左承载型`
  适合：右文左图、交替节奏页、人物或场景引导页

- `上下留白型`
  适合：横向流程、宽结构、章节转场、长标题页

- `中间留白型`
  适合：中心观点、四象限、中心辐射、关系页

- `全白承载型`
  适合：双栏对照、数据看板、重内容、复杂案例、表格页

## 四、按内容选布局的快速决策

如果一页只有一个结论：
- 优先选：中心观点型、章节转场型、结论收束型

如果一页是“一边讲、一边看”：
- 优先选：左文右图型、右文左图型

如果一页是两个世界对照：
- 优先选：双栏对照型

如果一页有三个并列点：
- 优先选：三卡片枚举型

如果一页是四类对象或二维分类：
- 优先选：四象限矩阵型

如果一页讲顺序和演进：
- 优先选：横向时间轴型、纵向步骤型

如果一页讲系统层级和模块：
- 优先选：分层架构型、中心辐射型

如果一页讲案例：
- 优先选：案例叙事型

如果一页主要是数字和图表：
- 优先选：数据看板型、全白承载型

## 五、单页施工时的布局拆解顺序

无论选哪一类布局，都建议按这个拆解顺序施工：

1. 先定主结构
2. 再定标题区
3. 再定主视觉或结构底板
4. 再定正文区
5. 最后补位和修平衡

不同布局的施工重点不同：

- 图主导页：
  先看主视觉是否成立，再决定文字压哪里

- 文主导页：
  先看版心和对齐线是否成立，再补轻视觉

- 架构页：
  先做无字骨架，再补标签和说明

- 案例页：
  先做情境图，再补“场景、做法、结果”卡片

## 六、最常见的布局误用

- 把所有页都做成左右分栏，整套没有节奏
- 明明只有一个观点，却硬塞成三卡片
- 明明是重内容页，却还想保留大面积主视觉
- 架构图没有层级，只是把一堆模块摆在一起
- 对照页两边权重不一致，比较关系失真
- 案例页只有漂亮场景，没有业务逻辑
- 每种布局都想加装饰，最后没有重点

## 七、推荐做法

- 一套 deck 不要超过 `4-6` 种主结构
- 同一章节内尽量保持相近节奏，但不要完全重复
- 封面、章节、架构、案例、尾页这五类页最好单独对待
- 内容页尽量从“左文右图、右文左图、全白承载、中心观点、宽流程”这几类里轮换
- 一页只保留一个视觉焦点，不要主图、卡片、图标、标题都在抢
