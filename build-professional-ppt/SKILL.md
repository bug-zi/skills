# Build Professional PPT

用于把 PPT 当成一个分阶段施工项目来做，而不是一次性吐一套页面。核心目标是先定真实身份和风格系统，再定母版、设计规范、大纲、逐页成图、审查、讲稿和交付导出文件。视频、PPTX、PDF、Word 都是最终成图后的导出后处理，不参与页面视觉生产。

## When to Use

- 用户要做正式汇报、课程、培训、产品介绍、方案汇报、路演 deck、高校或政企正式材料
- 用户希望先定风格，再定母版、`design.md`、大纲和逐页页面
- 项目需要沉淀可复用的风格库、模版库和施工资产
- 用户已有一套成图，但需要抽象成稳定风格或做系统化审查与微调
- 用户需要在最终成图和讲稿之后导出带语音、字幕的旁白视频

## When Not to Use

- 只是改一页里的几处小字
- 用户只要文案，不要视觉系统
- 用户只要可编辑 `.pptx`，且更适合直接使用 PowerPoint 装配 skill
- 用户只要视频剪辑创作，但没有最终页图和逐页讲稿作为输入

## Hard Stops

- 只要 `build-professional-ppt` 被显式激活，就不要同时采用通用 `PowerPoint` skill 的 builder 路线。
- 旧项目成图、旧 `.pdf`、旧 `.pptx` 可以作为参考样式、内容来源或在用户明确授权下沿用；但在没有明确授权时，不能直接把它们当成新项目首版交付。
- 对一个新项目，默认要按：`调研 -> 确认 -> 母版 -> 大纲 -> 逐页文字与素材整理 -> imagegen 正式成图` 开工。
- 如果发现自己准备写 builder、接入旧 deck、批量复制旧成图、先导出 `v1-base.pptx/pdf` 再说，这都视为偏航，必须停下并回到当前确认阶段。

## Important Three Times

工作流程重要事说三遍：

- `先分析，先调研，先确认，先母版，再整理逐页文字与素材，最后直接正式成图。`
- `先分析，先调研，先确认，先母版，再整理逐页文字与素材，最后直接正式成图。`
- `先分析，先调研，先确认，先母版，再整理逐页文字与素材，最后直接正式成图。`

工具原则重要事说三遍：

- `视觉主工具只有 imagegen。视觉主工具只有 imagegen。视觉主工具只有 imagegen。`
- `不要 builder，不要代码排版，不要 build_deck.mjs。不要 builder，不要代码排版，不要 build_deck.mjs。不要 builder，不要代码排版，不要 build_deck.mjs。`
- `旧版可参考、可提炼、可在授权下沿用，但不能默认直接当新项目首版交付。`
- `视频导出只能在最终成图和讲稿定稿之后。视频导出只能在最终成图和讲稿定稿之后。视频导出只能在最终成图和讲稿定稿之后。`

## Core Contract

### First-Turn Contract

- 先判断当前请求处于哪一个阶段，不要默认把整套流程一口气跑完。
- 开工前先做一次“冲突 skill 检查”。如果发现通用 `PowerPoint` skill、builder 路线或“可编辑 PPTX 代码排版”需求也在同时被触发，要先提醒用户：当前应只保留 `build-professional-ppt`，不要并行启用通用 `PowerPoint` skill。
- 如果发现冲突信号，优先使用下面这段固定提醒话术，不要自由发挥成含混表述：
  - `检测到当前项目可能同时触发了通用 PowerPoint skill。为了避免切到代码 builder 路线，请先只保留 build-professional-ppt 再继续。如果你要的是可编辑 .pptx 且接受代码排版，请明确改用 PowerPoint skill。`
- 发出这条提醒后，先停在当前阶段，不要继续页面生产，等用户明确确认保留哪条路线。
- 如果用户只要某一个阶段的结果，例如只要大纲、只要风格确认、只要母版，就停在该阶段，并明确进入对应确认关口。
- 没有明确确认通过前，不要擅自进入下一阶段。
- 默认优先级永远是：`设计确认 -> 母版确认 -> 大纲确认 -> 正式逐页成图`。
- 如果用户明确说“请先生成 PPT 大纲跟我确认”，那就只做大纲确认包，不要继续做母版或正式页面。

- 这个 skill 的视觉主工具始终只有一个：`imagegen`。
- 视觉动作只分两类：`生图` 和 `微调图`。
- 执行链路默认是：`找场景提示词模板 -> 套入当前需求 -> 调用 imagegen 生图或微调图 -> 复核 -> 归档`。
- 开始任何阶段前，先查看 `references/tool-usage-matrix.md`，确认当前阶段允许使用的主工具、辅助工具和禁止工具。
- 只有发生视觉决策或页面视觉变化的阶段才调用 `imagegen`。`design.md`、大纲、讲稿、日志整理默认不强制生图。
- 固定顺序是：`分析项目与现有资料 -> 调研查资料并定设计方向 -> 设计确认 -> 建立输入上下文与资源库 -> 生成母版组 -> 母版确认 -> design.md -> 大纲内容 -> 大纲确认 -> 逐页文字与素材整理 -> 逐页成图 -> 审查与微调 -> 讲稿生成 -> 交付导出`。
- 如果用户需要旁白视频，视频导出也必须排在最终逐页成图和最终讲稿之后，默认链路是：`最终页图 -> 逐页讲稿 -> MiniMax TTS 逐页语音 -> 图片+音频合成片段 -> 合并 MP4 -> 字幕校验`。
- 母版确认和大纲确认通过后，默认下一步不是继续生成设计总板、页型缩略图、章节分镜、10 页总览拼板或“第一批参考视觉”，而是整理逐页文字和素材，直接在已确认母版上生成正式页。
- 普通内容页默认链路是：`选母版 -> 整理本页文字与素材 -> 直接图文一体整页成图`。只有复杂架构页、流程页、功能图页才进入结构框定和分件拼装。
- 如果用户显式启用了 `build-professional-ppt`，本 skill 优先于通用 `PowerPoint` skill。不要切换到 JS builder、`build_deck.mjs`、`@oai/artifact-tool` 或 codex-primary-runtime/slides 路线来生产页面。
- 如果检测到以下任一冲突信号，先提醒用户关闭或不要继续启用通用 `PowerPoint` skill，再继续本 skill：
  - 用户同时提到 `$PowerPoint`、PowerPoint、PPTX builder、editable deck
  - 当前对话里已经出现 `build_deck.mjs`、artifact-tool、preview render、output.pptx 抽查等 builder 迹象
  - 当前任务目标被描述成“代码排版生成可编辑 PPTX”
- `PowerPoint` skill 或任何 builder 路线最多只能在最终导出阶段承担“把最终页图封装为一图一页的 `.pptx`”这类后处理动作，不能反向接管页面设计、页面排版、母版生成或逐页布局。
- 正式交付目录固定为：`风格目录`、`模版目录`、`设计规范`、`PPT大纲`、`素材目录`、`成品目录`。
- `风格目录` 至少维护一类标准风格和一类项目参考样式。`手绘白板风`、`科技未来风` 都属于标准风格；项目当前 `成图/` 或 `成品目录/01-逐页成图/` 只能抽象为“项目参考样式”，不能直接当成通用风格名。
- `模版目录` 至少维护四类常见需求：`汇报材料`、`课程`、`培训`、`产品介绍`，并写清章节编排和内容要求。
- 这个 skill 里的“母版”和“模板”是同义词，指后续用于填充真实内容的空效果底图。
- 母版不等于风格板。母版的核心作用是统一气质、统一留白和统一承载区。默认先做 `5` 张典型母版：封面、目录或章节页、两张内容页、结尾页。
- 风格一致是第一要求。母版组先统一色盘、材质、图像处理、装饰语言和场景气质，再区分封面、目录、内容页、结尾页的角色差异。
- 涉及机构或品牌身份的视觉元素必须先主动找真实来源。建筑、校徽、校色、校训、门头、雕塑、石刻、场馆、产品界面、品牌纹样、场景照片等，优先来自官网、官方物料或用户提供素材。
- 如果真实来源不足，必须退回到通用元素，而不是伪造一个“看起来像真的”元素。允许用抽象图形、通用书本、课堂器物、通用平台图标、通用数据图示、中性纹理、抽象波形、网络节点等，不允许伪造具体学校主楼、假校训、假石刻、假印章、假产品 UI、假地标。
- 风格总板、设计总板、组件总板可以作为分析或说明资产存在，但不能替代真正的母版组。
- 在风格阶段，必须额外生成一张面向用户确认的 `设计规范效果图`。它不是母版，也不是最终页，而是一张把封面预览、色盘、字体方向、图像语言、材质纹理、图示语言、页面节奏和示例页缩略图整合在一起的确认板。
- 生成母版组前，先参考 `references/master-examples.md`；如果 `assets/master-examples/` 里已有示例图，也要先看示例图区分“风格总板”和“母版组”。
- 每页必须先生成一张完全空的背景图，再进入图文一体整页成图。空背景图里不允许出现可读文字、假正文、假卡片标签或伪完成页面。
- 逐页施工时，优先从母版组里选择合适的空母版页；只有当前页无法被已有母版承载时，才允许派生新的空白变体。
- 母版页应该像“封面背景”“目录背景”“内容页承载背景”那样，为标题、正文、图表预留大片浅色留白；视觉元素尽量压在边缘、底部或单侧，不预画具体业务结构。
- 最终页面必须是图文一体成图，不允许停留在“只有效果、没有真实文字内容”的半成品。
- 复杂示意图、架构图、流程图允许先框定页面结构，再分区生成子图，最后拼装为整页；但子图也应尽量承载真实内容，而不是假字占位。
- 内容页不能千篇一律。不要连续多页使用同一布局方向、同一卡片数量、同一视觉节奏，除非内容逻辑明确要求。
- 内容、大纲、讲稿、最终导出文件必须一致。页序、标题、主判断、案例名、章节名变化后，要同步更新相关文件。
- 在进入正式逐页成图前，必须经过 `设计确认`、`母版确认`、`大纲确认` 三个关口。用户没有明确说“可以”“继续”“按这个做”“通过”，都不能视为确认通过。
- 三个确认关口都要写入 `设计规范/confirmation_log.md`。用户如果只给修改意见，本轮状态只能记为 `待修改`，不能记为 `已确认`。
- 这个 skill 的页面真相源必须是：`设计规范/design.md`、`素材目录/01-母版图/`、`素材目录/03-逐页素材/`、`PPT大纲/`。不允许把脚本坐标、代码函数、前端组件树当成页面真相源。
- 任何被替换的正式文件都不能直接删除，必须移入最近的 `old/`，并记录到 `设计规范/process_log.md`。
- 不允许使用 `python3 - <<'PY'`、临时 Python 脚本、`python-pptx`、绘图库或其它 Python PPT 库直接绘制、拼装、排版页面。
- 不允许使用 JavaScript、TypeScript、`@oai/artifact-tool`、HTML/CSS、Canvas、SVG、前端坐标脚本、浏览器截图脚本或任何代码驱动的排版引擎，从零定义视觉规则、画母版、画正式页。
- 不允许创建 `build_deck.mjs`、builder 脚本、preview 渲染链路或可编辑文本排版工程来替代本 skill 的 `imagegen` 施工流。
- Python、JS 或其它代码只能用于导出、校验、归档、重命名、拼联系列预览或 PDF 合成，不能参与页面生产本身。

## Required Workflow

### -1. 分析项目与现有资料

- 在任何调研和设计动作前，先把项目目标、项目类型、现有语料、已有资产、旧版可用性和风险分析清楚。
- 这一阶段默认先读：
  - 用户需求
  - 项目目录里的文档、截图、旧成图、旧 pdf/pptx
  - 已有讲稿、方案、产品文档、汇报稿
- 至少要分析清楚：
  - 这套 PPT 本质上是什么类型
  - 用户真正要的是“介绍 / 汇报 / 课程 / 培训 / 方案 / 路演”中的哪一种
  - 当前项目哪些资料是真实主语料
  - 旧资产哪些只能参考，哪些可以复用
  - 哪些地方最容易让模型滑向 builder、旧版复制或假元素
- 这一阶段的核心产物是分析结论，不是生图。
- 推荐落成：
  - `设计规范/project_analysis.md`
  - 或在 `research_brief.md` 开头单列“项目分析”章节

### 0. 调研查资料并定设计方向

- 对学校、医院、政府、文化机构、品牌项目，先查官方来源。
- 同步查看项目已有 `成图/`、`成品目录/01-逐页成图/` 或历史页面，把可复用特征抽象成“项目参考样式”。
- 这一阶段要同时沉淀：
  - `研究结论`
  - `风格总表`
  - `调研风格板`
  - `设计规范效果图`
  - `元素来源清单`
  - `项目参考样式` 的特征总结

### 0.5 设计确认

- 在进入母版阶段前，必须先向用户展示当前设计方向。
- 设计确认包至少包括：
  - `research_brief.md`
  - `设计规范/设计规范效果图.png`
  - `设计规范/element_source_log.md`
  - 已选风格方向说明
  - 调研风格板或 moodboard
  - 设计关键词、色盘、图像处理方式、气质判断
- `设计规范效果图` 必须足够像一张用户能快速理解的设计规范板，而不是只给零散图片拼贴。
- 这张图至少应同时表达：
  - 封面气质预览
  - 色彩体系
  - 字体方向
  - 建筑、人物、产品或场景图像语言
  - 材质与纹理
  - 图示或图标语言
  - 页面节奏和 `4-6` 张页型缩略图
- 这一关只确认“设计方向是否对路”，不是确认最终页面。
- 用户明确通过后，才能进入下一阶段；如果用户给的是修改意见，就回到调研或风格整理继续改。

### 1. 建立输入上下文与资源库

- 读取用户对话、讲稿、`design.md`、大纲、历史页面、参考图、素材目录。
- 初始化六类业务目录与 `old/` 子目录。
- 按项目类型选用 `模版目录` 中的章节编排基线。

### 2. 生成母版组

- 默认先生成 `5` 张典型母版，再按需要补充变体。
- 这 `5` 张默认是：
  - `01` 封面空母版
  - `02` 目录页或章节页空母版
  - `03` 内容页空母版 A
  - `04` 内容页空母版 B
  - `05` 结尾页空母版
- 这 `5` 张不能只是同一张图的小改色或小换位。至少要拉开：
  - 封面更有开场仪式感
  - 目录或章节页更像转场
  - 内容页 A/B 的承载方向或留白节奏明显不同
  - 结尾页有明确收束感
- 但这种角色差异不能靠“每张颜色都不一样”来实现。角色差异主要来自：
  - 留白位置
  - 视觉重心
  - 阅读节奏
  - 场景裁切方式
  - 装饰强弱
- 如果项目内容更复杂，再从这 `5` 张基础母版里派生：
  - 更多内容页空白变体
  - 可选复杂页空白变体
- 母版先解决承载逻辑和页面留白，再解决装饰语言。
- 母版必须和已选风格保持同一个视觉系统，而且必须是空图，不提前写入具体页内容，也不提前画出具体模块骨架、关系图或示意流程。

### 2.5 母版确认

- 在写完整 `design.md` 或进入正式定页前，必须先让用户确认母版组是否满意。
- 母版确认包至少包括：
  - `5` 张基础空母版预览
  - 每张母版的页型角色说明
  - 这一套母版的统一风格说明
- 用户主要确认：
  - 风格是否统一
  - 封面、目录、内容、结尾的角色差异是否足够
  - 留白是否能承载后续内容
- 用户未明确通过前，不得进入正式逐页成图。

### 3. 设计 `design.md`

- 把风格、模板、母版组和页型规则写成稳定规范。
- `design.md` 里必须写清标题系统、布局安全区、正文密度、图片规则、特殊页约束和反同质化规则。
- `design.md` 默认是文字规范文件，不是新一轮中间图生产阶段。母版确认通过后，不要再默认生成新的风格总板、页面节奏板或页型预演图。

### 4. 梳理大纲并完善内容

- 先读讲稿或原始材料，再抽叙事主线。
- 每页都要明确：页码、页型、主判断、标题、信息单元、素材需求、对应母版、是否复杂示意图。
- 大纲不是纯文字目录，而是“内容 + 页型 + 风格意图 + 成图方式”的施工清单。

### 4.5 大纲确认

- 在进入第 `5` 阶段逐页成图前，必须向用户展示可执行大纲。
- 大纲确认包至少包括：
  - `narrative_plan.md`
  - `PPT大纲-逐页内容.md`
  - 章节划分、页数、页型、主判断、对应母版
- 用户主要确认：
  - 页序是否合理
  - 章节和标题是否成立
  - 页数是否合适
  - 每页主判断和内容单元是否对
- 用户未明确通过前，不能开始正式逐页页面生成。

### 4.6 逐页文字与素材整理

- 在正式逐页成图前，先把每一页最终要上的文字和素材收束好。
- 这一阶段默认不生成新的中间视觉板，不产出章节分镜、页型缩略图拼板或“第 1 批参考视觉页”。
- 每页至少整理：
  - 最终标题
  - `3-6` 个信息单元
  - 结论句或页底判断
  - 已确认可用的真实素材
  - 缺失素材的通用 fallback 方案
  - 所选母版页
  - 是否复杂页
- 这些内容优先写入当前页的 `00-施工卡/内容与素材清单.md`，作为后续成图真相源。

### 5. 逐页生成页面成图

这一阶段必须逐页闭环，不允许“整套先上标题，再整套上图，再整套补字”。
默认链路是：`整理本页文字与素材 -> 选母版 -> 直接图文一体成图`。页面结构框定和复杂拼装是少数复杂页的可选路径，不是默认路径。

每页固定按下面顺序施工：

#### 5A. 页面施工卡与内容包

- 写清页码、页型、主判断、所用风格、所用模版、主布局结构、是否复杂页。
- 同时锁定本页最终标题、短正文、标签、结论句、必需素材和 fallback 素材。
- 先决定当前页是：
  - `简单页：选空母版 -> 图文一体整页成图`
  - `复杂页：选空母版 -> 结构框定 -> 子图生成 -> 拼装整页`

#### 5B. 选用或派生空母版页

- 先从母版组中选择当前页最合适的空母版页。
- 如果现有母版承载不了当前页，再基于该母版系统派生新的空白变体。
- 空母版页只允许保留背景气氛、留白方向和主承载区，不允许提前出现真实文字内容、假内容、具体业务图标关系或半成品结构示意。

#### 5C. 页面结构框定（仅复杂页默认进入）

- 简单页默认跳过这一步，直接进入 `5D`。
- 对复杂页，框定子图分区、连接关系、说明区、结论区。

#### 5D. 图文一体整页成图

- 直接生成当前页的完整页面图，标题、短正文、图像、卡片、标签一起进入最终图。
- 不要先出一张漂亮但没有真实文字内容的效果图，再把字后贴上去。

#### 5E. 复杂示意图拆分与拼装

- 仅在架构页、流程页、功能页、复杂案例页使用。
- 先按结构框定生成若干子图，再拼装回整页。
- 子图可按“左侧说明块 / 中央结构块 / 右侧结果块”或“顶部结论条 / 中部流程 / 底部价值条”拆分。

#### 5F. 局部微调与统一

- 如有局部不稳，再用 `imagegen` 补做局部纹理、小图标、局部重生成或统一素材。
- 微调的目标是统一，不是引入新风格。

#### 5G. 单页复核

- 检查标题是否表达判断，图文是否抢位，内容是否只讲清一个主判断。
- 检查当前页与前后页是否过于相似，必要时回退改变布局方向或信息组织方式。

#### 5H. 资产归档

- 把所选母版、派生空白变体、框定图、子图、拼装预览、最终页都放回当前页素材目录的正确子目录。
- 写入 `old/` 归档和 `process_log.md`。

### 6. 审查与微调

- 必须从 `逻辑`、`内容`、`样式`、`布局`、`一致性` 五个维度正式审查。
- 可直接统一的问题优先当场微调。
- 结构性问题要明确回退到大纲、设计规范或逐页施工阶段。
- 审查结果必须落成 `设计规范/review_report.md`。

### 7. 根据成图生成讲稿

- 讲稿必须基于最终页序和最终页面来写。
- 默认产出：
  - `speech_script.md`
  - `speaker_notes.md`
  - `slide_speech_map.md`

### 8. 导出交付文件

- 导出分四类：
  - `PDF`：基于最终逐页成图合成
  - `PPT`：把最终页图封装为一图一页的 `.pptx`
  - `Word`：把最终讲稿或汇报资料导出为 `.docx`
  - `Video`：基于最终逐页成图和最终讲稿生成逐页语音、字幕和 `.mp4`
- 导出必须基于最终逐页成图、最终大纲和最终讲稿，不允许在导出阶段重做视觉。
- 视频导出只能使用 `scripts/generate_minimax_slide_video.py` 这类后处理脚本：允许调用 MiniMax TTS、`ffmpeg`、`ffprobe`；不允许用视频脚本或字幕脚本重画页面、贴字排版或生成新视觉。

### 9. 校验与交付

- 检查目录、版本归档、一致性、页序、讲稿映射、PDF 完整性。
- 检查最终交付是否真的按照建构式流程完成，而不是跳步拼凑。

## Existing Deck Mode

- 这一模式只在用户明确说“沿用现有页面改”“基于旧版迭代”“不要从零做”时启用。
- 如果用户没有明确要求沿用旧版，就算项目根目录已有 `成图/`、`.pdf`、`.pptx` 或历史页面，也只能把它们当作参考样式与素材来源，不能直接复制成新项目首版交付。
- 如果用户给的是已有页面，不必强行推倒重来，但仍要先回补缺失的调研结论、风格库、模版库、母版组或 `design.md`。
- 如果项目根目录已有 `成图/` 或 `成品目录/01-逐页成图/`，默认先把它抽象为 `风格目录/02-项目参考样式-当前成图/`，用于理解视觉语言，不自动视为可直接接入的新项目成品。
- 如果现有页面只是不够稳，且用户明确要求沿用，优先进入“审查与微调”，而不是默认重做整套。

## Non-Negotiables

- 不允许跳过调研阶段直接堆页面。
- 不允许没有 `design.md` 就批量做页。
- 不允许把风格板、设计总板、组件总板误当成母版组。
- 不允许把程序化生成 PPT、代码排版 PPT、工程化导出 PPT 当成这个 skill 的主体做法。
- 不允许在母版确认和大纲确认通过后，默认继续生成章节分镜、页型缩略图拼板、10 页总览或“第一批参考视觉页”。
- 不允许把最终页面做成“背景图 + 后贴文字”的两张皮流程。
- 不允许把复杂示意图直接塞成一整团，无法承载阅读路径。
- 不允许用 Python、JS、`@oai/artifact-tool`、HTML/CSS、Canvas、浏览器截图链路替代 `imagegen` 成图。
- 不允许只改页面不改大纲，也不允许只改大纲不改页面和讲稿。
- 不允许页面之间风格完全散掉，也不允许内容页全部长得一样。
