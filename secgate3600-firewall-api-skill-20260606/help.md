# secgate3600-firewall-api-skill-20260606 研究说明

## 1. 这个 skill 是做什么的，提供哪些功能？

这个 skill 面向网神 / 奇安信 SecGate 3600 / NSG 防火墙的 RESTful API 运维，目标版本主要是 `V3.6.6.0`。它不是通用防火墙 skill，只适用于该设备的 `/v1.0/login`、`/v1.0/rest/`、`/v1.0/out` 这一套 API。

它提供的核心功能包括：

- 查询和解释内置的 SecGate 3600 RESTful API 手册、索引、摘要和 API 覆盖矩阵。
- 通过脚本登录防火墙 API，保持 `PHPSESSID` 和 `token` cookie，再调用模块 / 函数式 REST 请求。
- 执行只读快照，读取系统信息、安全策略、地址对象、地址对象组、黑名单、批量域名黑名单、syslog 配置等。
- 根据 API 覆盖矩阵批量测试只读接口。
- 检查本地“翻墙”管控相关地址对象与同名安全策略。
- 以 dry-run 方式生成变更计划，并在显式加 `--apply` 时写入防火墙地址对象。
- 支持直接连接、防火墙不可达时通过 DOOPS 跳板执行，以及 `auto` 自动回退。

需要特别注意：这个 skill 具有真实生产设备运维能力，不只是文档检索能力。它的脚本可以在满足条件时修改防火墙对象。

## 2. 这个 skill 的结构是什么？包含哪些文件？注入 prompt 后如何工作，流程是什么？

目录结构如下：

- `SKILL.md`：skill 的入口说明，定义触发场景、可用文档、连接规则、支持工作流、API 形态、CLI 命令、安全写入流程。
- `scripts/netentsecctl.py`：主要 CLI，支持登录、原始 REST 调用、模块 / 函数调用、只读批量测试，以及 `nsg-address-ips` 地址对象发布。
- `scripts/nsg_snapshot.py`：只读快照脚本，读取关键配置段并写入 `snapshots/nsg_snapshot_<timestamp>.json`。
- `scripts/publish_block_objects.py`：从 Excel 工作簿读取 `翻墙风险IP` 和 `翻墙风险域名`，生成计划或写入同名地址对象。
- `config/connection.example.json`：连接配置样例。
- `payloads/fanqiang_forbid_internet_ips_20260601.txt`：示例 / 本地使用的 IP 列表 payload。
- `references/operation-guide.md`：操作指南，说明账号设置、测试顺序、传输模式、成功信号和故障排查。
- `references/api-summary.md`：本地验证摘要，记录登录、cookie、模块名、分页限制和常用只读调用。
- `references/api-coverage-matrix.md` / `.csv`：从手册提取出的模块 / 函数矩阵，区分 read 与 write_or_stateful。
- `resources/nsg-firewall/`：SecGate 3600 V3.6.6.0 手册 PDF、提取文本、摘要、索引，以及旧版 NSG 手册资料。
- `agents/openai.yaml`：OpenAI 侧展示名、短描述和默认 prompt，并允许隐式调用。
- `.gitignore`：忽略 `config/connection.local.json` 和 `snapshots/`。

当 prompt 注入后，它会让模型遵循大致流程：

1. 先确认用户任务确实属于 SecGate 3600 / NSG 防火墙 RESTful API。
2. 优先检索内置 API 索引、提取文本和覆盖矩阵，找到正确模块和函数。
3. 遇到本地设备操作时，先做只读查询或快照。
4. 对写入类任务，先从快照生成逻辑变更计划，默认 dry-run。
5. 只有用户明确要求并使用 `--apply` 时才实际写入。
6. 写入前重新读取目标对象和策略，避免基于过期快照操作。
7. 写入后再次读取或快照验证最终状态。

它的设计重心是“文档检索 + 可重复 CLI + snapshot-first 变更控制”。

## 3. 它有哪些优点？有哪些弱点、短板或限制？

优点：

- 针对性很强：专门面向 SecGate 3600 / NSG RESTful API，包含当前版本手册、旧版手册、索引和覆盖矩阵。
- 流程较完整：从账号启用、登录、cookie 保存、只读快照、dry-run、写入前复核、写入后验证都有说明。
- 有实际 CLI：不只是提示词，提供了可重复执行的 Python 工具。
- 风险分层较清楚：API 覆盖矩阵区分 read 与 write_or_stateful，写入命令默认不 apply。
- 考虑了网络环境：支持 direct、doops、auto 三种传输模式，能处理本机无法直连防火墙的场景。
- 对本地业务对象有沉淀：如 `翻墙禁止上网`、`翻墙风险IP`、`翻墙风险域名` 这些对象和同名策略的操作规则。

弱点和限制：

- 脚本内硬编码了真实连接信息和明文密码。这是最高优先级安全问题，尤其不适合进入共享仓库、公共仓库或被同步到多端环境。
- `SKILL.md` 声称不要把凭据写入脚本、说明和产物，但当前脚本实际违反了这一原则。
- 可写能力集中在特定对象发布场景，对其他 write_or_stateful API 虽可通过通用 CLI 调用，但需要人工构造 payload，风险较高。
- `publish_block_objects.py` 中存在重复代码块迹象，维护成本偏高。
- 部分资料是从 PDF 自动提取，摘要中可见断行和 OCR / 提取噪声，具体字段仍需回到 PDF 或原文核对。
- 当前操作指南记录的最新本地验证仍卡在防火墙 REST API 配置 / 账号 / trusted host 问题上，说明 live 流程未完全闭环。
- 对 DOOPS 环境有强依赖，且内置了特定 `doops_cwd` 与 target，迁移到其他机器或团队时需要重新配置。
- `agents/openai.yaml` 允许隐式调用，考虑到它有真实设备操作能力，这个触发策略偏激进。

## 4. 适合谁使用？不适合谁使用？

适合：

- 负责 SecGate 3600 / NSG 防火墙运维的网络安全工程师。
- 熟悉 RESTful API、地址对象、安全策略和变更审批流程的防火墙管理员。
- 需要把“风险 IP / 风险域名清单”批量发布到固定防火墙对象的内部运维人员。
- 有 DOOPS 跳板环境、需要从受信内网节点调用防火墙 API 的团队。
- 需要快速查找 SecGate 3600 API 模块 / 函数名、请求结构和错误码的人。

不适合：

- 不具备防火墙变更权限或不了解策略影响的人。
- 只想学习通用防火墙 API、Fortinet、Palo Alto、Cisco ASA 等其他厂商 API 的用户。
- 没有 SecGate 3600 V3.6.6.0 或兼容 NSG 设备的环境。
- 不能接受脚本内含敏感连接信息的团队。
- 对生产变更没有审批、回滚和双人复核流程的场景。
- 公共 prompt library 或需要低风险自动调用的 agent 环境。

## 5. 适合哪些实际场景？主要解决什么需求和痛点？

适合的实际场景：

- 快速确认 SecGate 3600 某个功能对应的 REST module / function。
- 读取防火墙系统状态、安全策略、地址对象、黑名单、syslog 等配置快照。
- 在变更前生成防火墙配置快照，作为分析和回滚参考。
- 维护 `翻墙禁止上网`、`翻墙风险IP`、`翻墙风险域名` 这类固定管控对象。
- 从 Excel 中提取风险 IP / 域名，并合并发布到目标地址对象。
- 在本地不能直连防火墙时，通过 DOOPS 跳板完成同样的 API 调用。
- 批量验证文档中提取的只读 API 是否可用。

主要解决的痛点：

- 厂商 API 手册长、模块函数多，人工查找效率低。
- SecGate 3600 登录后需要同时维护 `PHPSESSID` 和 `token`，容易踩坑。
- 地址对象和策略引用关系复杂，直接写入前需要安全检查。
- 防火墙管理面可能只能从特定内网或跳板机访问。
- 风险 IP / 域名清单需要重复导入，手工维护容易漏项或误删。

## 6. 是否有污染 prompt 库、降低 AI 效率或带来安全问题的风险？

有，而且需要重点治理。

Prompt 污染风险：中高。这个 skill 的触发描述很具体，按理不会误触太多普通任务。但它的 `agents/openai.yaml` 设置了 `allow_implicit_invocation: true`，并且 `SKILL.md` 内容很长，包含大量本地对象名、固定工作流和环境细节。如果在不相关任务中被注入，会浪费上下文并把模型行为引向本地防火墙运维。

效率风险：中。它捆绑了大量 PDF、提取文本、索引和矩阵；如果使用得当，索引和摘要能提升效率。但如果每次都读取大段手册或覆盖矩阵，会占用较多上下文。实际使用时应优先查索引和摘要，只在字段不确定时再查 PDF / 提取文本。

安全风险：高。原因包括：

- 脚本内硬编码真实防火墙地址、账号和明文密码。
- 脚本具备真实写入能力，包括修改地址对象成员。
- 支持 DOOPS 跳板执行，会把临时脚本、配置和 payload 推送到远端节点。
- `--apply` 是显式开关，但 agent 如果误判用户意图，仍可能执行真实变更。
- 输出报告包含 `base_url`、对象名、计划和部分新增域名，可能泄露内部网络和管控策略信息。
- 使用 `insecure_tls: true` 跳过证书校验，在受控内网中常见，但从安全基线看仍是风险点。

建议处理：

- 立即移除脚本中的硬编码明文密码，改为只从 `config/connection.local.json`、环境变量或交互式输入读取。
- 如果该 skill 会进入公共或多人共享仓库，先轮换当前 API 账号密码。
- 将 `allow_implicit_invocation` 改为更保守的触发策略，避免自动注入可操作生产设备的 skill。
- 对所有写入流程保留“先 snapshot、再 dry-run、明确确认、最后 apply”的强约束。
- 对 DOOPS 模式明确记录远端临时文件清理和凭据传输边界。
- 将真实设备信息、账号、路径等本地化配置放入被 `.gitignore` 忽略的本地配置文件。

总体判断：这是一个功能完整、实用性强、但安全敏感度很高的生产运维 skill。适合保留在受控的个人 / 内部技能库中使用；在同步、分享或开放给自动 agent 调用前，必须先处理硬编码凭据和隐式调用风险。
