# 翻墙管理_skill 研究说明

## 1. 这个 skill 是做什么的，提供哪些功能？

这个 skill 用于浙江音乐学院“翻墙”治理场景中的日志调查、证据复核和处置清单生成。它不是防火墙配置发布工具，也不是单次报告模板，而是一个面向多数据源日志分析的操作规范。

它覆盖的主要功能包括：

- 按日期或时间范围查询翻墙相关日志，例如今天、昨天、某一天、某个时间段。
- 查询 SFTP 239 翻墙设备日志，重点是 `tw_act_*` 和 `web_act_*`。
- 查询 172.16.15.20 上网行为管理日志，用于补充 MAC、账号、用户、姓名、访问对象、SNI、URL、应用标签等信息。
- 查询 172.16.15.6 / 7 / 8 防火墙 syslog 目录，在有日志时作为补充证据。
- 区分不同菜单和场景：`翻墙记录`、`国外访问`、`涉政敏感`、`挖矿线索`、`复核剔除`。
- 建立证据分级：`确认翻墙`、`高疑似代理/需复核`、`国外网站访问线索`、`涉政访问线索`、`挖矿线索`、`误判剔除`。
- 对常见误判做过滤，例如 Google / Chrome 更新、Safe Browsing、Android 后台服务、DNS-only 记录、零 MAC、弱关键词等。
- 输出面向交付的 Excel 清单和汇总表，而不是倾倒原始日志。

一句话概括：它是一个“翻墙治理日志调查与证据分级工作流”skill，核心目标是把多源日志变成可复核、可交付的处置清单。

## 2. 这个 skill 的结构是什么？包含哪些文件？注入 prompt 后如何工作，流程是什么？

当前目录结构很简单：

- `SKILL.md`：核心说明文件，包含数据源路径、访问方式、过滤规则、证据分级、查询流程、输出字段和交付标准。
- `agents/openai.yaml`：OpenAI 侧展示和触发配置，显示名为 `翻墙管理`，默认 prompt 指向浙江音乐学院代理/VPN、SFTP、20 上网行为、防火墙日志证据调查。

这个 skill 没有内置脚本、样例数据、模板文件或独立配置文件。实际执行时，需要由 agent 根据 `SKILL.md` 里的规则现场组织命令、grep 管道或临时分析脚本，并在日志所在机器或 DOOPS 目标上运行。

注入 prompt 后的典型流程是：

1. 明确用户要查的日期或时间范围，并把“昨天”“今天”等相对时间转换为 Asia/Shanghai 的具体时间。
2. 判断日志访问方式：优先检查本机 `/raid5/...`，不可用时走 DOOPS target `zy`，使用 `/proc/1/root/raid5/...` 路径。
3. 查询 SFTP `tw_act_*`，把它作为确认翻墙的主证据来源。
4. 查询 SFTP `web_act_*`，把它作为网站访问 / 涉政敏感证据来源，不与 `tw_act` 混为一类。
5. 查询 172.16.15.20 上网行为管理日志，用 `authlog` 补充 IP 对应的 MAC、账号、用户信息，用 `app_conn`、`proxy_identify`、`ssl_log`、`web` 补充访问行为。
6. 必要时检查 172.16.15.6 / 7 / 8 防火墙日志目录，只有文件存在时才作为证据来源。
7. 按证据强度分类，剔除误判或弱证据。
8. 输出紧凑结果，通常是 Excel 清单和汇总表。

它强调“在日志所在机器上分析”，不要把大日志下载到本地；只拉回 CSV、XLSX、JSON、证据样例等小型结果。

## 3. 它有哪些优点？有哪些弱点、短板或限制？

优点：

- 数据源边界清晰，分别说明了 SFTP、20 上网行为、防火墙 syslog 的路径和用途。
- 证据口径比较严谨，明确 `tw_act` 才是确认翻墙的主要证据，Google / 国外网站访问不等于翻墙。
- 对误判有较多经验规则，例如 Chrome 更新、Safe Browsing、公共 DNS、零 MAC、弱关键词挖矿误报。
- 输出字段和 Excel 交付规则比较完整，适合形成标准化处置清单。
- 支持 direct 和 DOOPS 两类访问模式，适配日志不在本机的真实运维环境。
- 对新手有一定保护：反复强调“不确定就标记需复核，不要隐藏不确定性”。

弱点和限制：

- 没有配套脚本，执行质量高度依赖 agent 临时写 grep / Python 解析逻辑的能力。
- `SKILL.md` 很长，注入后会占用较多上下文；如果只是查一个很小的问题，可能显得重。
- 数据源路径、IP、学校场景高度本地化，不适合作为通用翻墙检测 skill。
- `agents/openai.yaml` 允许隐式调用，可能在相关但不需要完整调查流程的任务里被过早注入。
- 目录名和 skill name 都是中文，某些 skill 运行环境或 marketplace 工具可能更偏好英文 / ASCII 名称。
- 它依赖 DOOPS target `zy`、`/raid5/...`、`/proc/1/root/...` 等本地环境；换环境后需要改路径和目标。
- 没有明确凭据管理说明，但实际运行 DOOPS 和读取日志通常涉及敏感权限。
- 它要求生成 Excel，但没有内置模板或脚本，格式一致性需要执行者自己保证。

## 4. 适合谁使用？不适合谁使用？

适合：

- 浙江音乐学院网络安全、信息化或运维人员。
- 需要复核代理/VPN、国外访问、涉政访问、挖矿线索的日志分析人员。
- 已经了解或可以访问 SFTP 239、172.16.15.20 上网行为日志、防火墙 syslog 的管理员。
- 需要把原始日志整理为处置清单、复核清单、涉政敏感汇总的值班人员。
- 希望在调查时保留证据分级和误判剔除理由的人。

不适合：

- 没有日志访问权限的人。
- 不在浙江音乐学院环境、不使用这些固定日志路径和设备的人。
- 想直接修改防火墙策略、地址对象或黑名单的人；这类工作应使用 `secgate3600-firewall-api` skill，并且需要明确审批。
- 想做通用网络取证、恶意软件分析、终端进程取证的人；这个 skill 主要看网络侧日志。
- 只需要高层管理汇报、不需要具体日志证据的人。

## 5. 适合哪些实际场景？主要解决什么需求和痛点？

适合的实际场景：

- 查询“昨天到今天有哪些确认翻墙记录”。
- 给某一天的 `tw_act` 翻墙记录补全 MAC、账号、姓名、访问摘要。
- 分析某个 IP / 账号是否只是访问 Google / YouTube，还是有确认翻墙证据。
- 单独查询涉政敏感访问，区分 `web_act` 主证据和 20 日志补充证据。
- 查询 OpenAI、YouTube、Facebook、X/Twitter 等主要国外网站是否有访问记录。
- 检查挖矿相关域名或协议线索，并过滤 `pool`、`xmr` 这类弱关键词误报。
- 生成 Excel 处置清单、国外访问汇总、涉政敏感明细、复核剔除记录。

主要解决的痛点：

- 日志分散在多个目录和设备中，人工查找容易漏。
- 不同日志证据强度不同，容易把“访问国外网站”误判为“确认翻墙”。
- 20 上网行为管理日志很大，不能粗暴下载到本地分析。
- MAC、账号、用户、姓名等身份信息需要从 authlog 补齐。
- 管理交付需要清晰表格，而不是原始日志碎片。
- 新手容易混淆 `tw_act`、`web_act`、20 日志、防火墙日志的证据意义，这个 skill 给了统一口径。

## 6. 是否有污染 prompt 库、降低 AI 效率或带来安全问题的风险？

有一定风险。

Prompt 污染风险：中。这个 skill 很长，而且场景高度本地化。如果在非浙江音乐学院、非翻墙治理、非日志调查任务中被注入，会占用上下文并把回答带向本地路径、设备 IP 和固定菜单。`allow_implicit_invocation: true` 会增加这种误触概率。

效率风险：中高。`SKILL.md` 内容非常完整，但也很重。对于简单查询，完整加载所有过滤规则、字段列表、交付标准可能不划算。更理想的结构是把核心流程保留在 `SKILL.md`，把长名单、字段映射、误判规则拆到 `references/` 文件中按需读取。

安全风险：中高。原因包括：

- 它涉及真实校园网络日志，可能包含 IP、MAC、账号、姓名、访问 URL、SNI、涉政敏感访问记录等个人和敏感信息。
- 它要求通过 DOOPS target `zy` 访问日志主机，实际执行需要较高运维权限。
- 如果执行者没有严格控制输出，可能把原始日志、个人信息或敏感访问证据泄露到对话或本地文件。
- 它可能生成处置清单，对个人账号产生管理影响，因此误判风险需要严肃对待。
- 它没有禁止写入远端文件，只是要求把分析输出放 `/tmp`；执行时必须避免修改原始日志或系统配置。

建议：

- 保留“只读日志调查”定位，明确禁止修改原始日志、删除日志、改设备配置。
- 将 `allow_implicit_invocation` 改得更保守，避免无意触发。
- 在正式使用前补充一个 `references/` 目录，把国外站点列表、涉政站点列表、挖矿关键词、误判白名单拆出来维护。
- 增加固定分析脚本或模板，减少每次临时写解析逻辑造成的不一致。
- 交付结果默认脱敏或最小化展示个人信息，只有在用户明确需要处置清单时才输出完整账号/MAC/姓名。
- 每次输出都说明证据来源和证据强度，避免把线索当结论。

总体判断：这是一个很实用的本地化日志调查 skill，适合做校园网络翻墙治理和处置清单复核；但它处理的是敏感网络行为数据，应该作为受控内部 skill 使用，不适合公开分享或泛化调用。
